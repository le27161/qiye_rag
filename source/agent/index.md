让模型调用工具并不困难，困难的是让一次行动有明确范围、能够检查，也能够在出错时停下来。这里不追求“全自动”的故事，而是关注模型如何进入一个可控的业务系统。

## 用问数系统串起工程问题

问“华东上个月卖得怎么样”，表面是在要一个数字，背后却涉及业务口径、数据权限和数据库执行。这组文章用一个持续的电商场景展开，而不是把项目拆成安装、配置、接口调用的步骤。

- [从一句业务问题到一张结果表：问数 Agent 的系统设计](/agent/nl2sql-architecture/)：先看整体链路，以及 RAG 在其中的位置。
- [问数的难点不只在 SQL，而在业务语义层](/agent/semantic-metadata/)：把字段、维度值、指标与关联关系组织成可靠上下文。
- [用 LangGraph 编排问数：状态、并发与有边界的重试](/agent/nl2sql-workflow/)：让检索分支汇合，让修正经过重新校验。
- [SQL 能执行，不代表它可以执行](/agent/sql-safety/)：分清语法检查、权限控制、成本限制和业务正确性。
- [问数 Agent 的最后一公里：结果解释、接口与评测](/agent/product-and-evaluation/)：把过程变得可见，同时保留拒绝、澄清和核对的能力。
