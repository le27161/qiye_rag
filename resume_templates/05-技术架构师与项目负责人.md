# 简历模板五：技术架构师 / 项目负责人

## 项目名称

**KnowForge 企业级多场景 RAG 知识问答平台**

## 项目周期

20XX.XX - 20XX.XX（按实际经历填写）

## 项目背景

企业 RAG 项目不能停留在单一 Demo，需要同时解决多业务场景接入、知识库版本治理、FAQ 与文档知识协同、权限隔离、质量门禁、可观测性和部署复现问题。KnowForge 以 FastAPI + LangChain + Milvus + MySQL 为核心，构建了覆盖 8 个业务场景的 RAG 平台，并为后续 Agent、复杂工具编排和更严格的知识治理预留扩展点。

## 技术架构

| 层次 | 技术选型 |
|---|---|
| 接入层 | FastAPI、WebSocket、REST API、静态页面 |
| 编排层 | RAG Pipeline、`QAService`、`QueryServiceContext`、Prompt Profile |
| 检索层 | Milvus Hybrid Search、BGE-M3、BM25BuiltInFunction、BGE-Reranker-Large |
| 治理层 | MySQL 知识库版本控制面、IndexManifest、DataScope、质量门禁 |
| 评测层 | 主链路评测、追问评测、入库质量、性能基线、RAGAS 补充评测 |
| 观测层 | LangSmith Trace、Dataset、Annotation、Experiment |
| 部署层 | Docker Compose，MySQL + etcd + MinIO + Milvus + API |
| 文档层 | MkDocs Material、流程图、架构图、运行手册 |

## 核心能力

1. **多场景平台化**：8 个业务场景通过 `scenario.toml` 接入，场景、source、collection、Prompt 上下文解耦。
2. **RAG 主链路标准化**：将意图、检索策略、查询改写、检索、重排、上下文、Prompt、生成和历史写入拆成稳定阶段。
3. **检索架构升级**：采用 Milvus Dense + BM25 Hybrid Search，配合 CrossEncoder 重排和动态检索计划。
4. **知识库版本治理**：MySQL 管理版本状态和 active 指针，Milvus 数据通过 `kb_version` 过滤实现多版本共存。
5. **增量入库机制**：IndexManifest 记录文件 fingerprint、chunk ids、embedding 版本和 chunk schema，支持未变化文件跳过和跨版本复用。
6. **数据安全边界**：DataScope 四维隔离模型统一控制 tenant、dataset、visibility、allowed_roles。
7. **质量保障体系**：入库质量门禁、主链路评测、追问评测、性能基线和 LangSmith Bad Case 闭环。
8. **可复现交付**：通过 Docker Compose、运行检查脚本、MkDocs 文档站点和可视化流程图降低部署与维护成本。

## 个人职责

- 主导整体技术方案设计，定义 RAG Pipeline 分层、模块边界、数据契约和异常处理策略。
- 负责技术选型，确定 FastAPI + LangChain + Milvus Hybrid Search + MySQL + LangSmith 的组合方案。
- 规划多场景配置体系，使业务场景、source 白名单、collection、Prompt 上下文和评测样本可以独立维护。
- 设计知识库版本治理方案，将版本元数据、active 指针和入库统计收敛到 MySQL，线上查询统一按 active `kb_version` 过滤。
- 设计质量门禁体系，将入库质量、检索评测、追问评测、性能基线和 Bad Case 回归纳入发布前检查。
- 协调后端、检索、数据治理、质量评测和文档可视化等方向的交付边界，保证代码、文档、演示和运行脚本一致。
- 维护 Docker Compose 部署和运行检查方案，支持本机、容器和远程环境的差异化部署。
- 建立架构文档、讲义式技术文档、流程图和使用手册，方便项目移交和持续维护。

## 项目成果

- 完成多场景企业 RAG 平台的端到端交付，覆盖问答、检索、入库、版本、隔离、评测、观测和部署闭环。
- 将知识库更新从“直接覆盖”改为“候选版本构建 + 质量门禁 + active 指针切换”，降低错误资料影响线上问答的风险。
- 用 Milvus Hybrid Search 替代本地自研关键词召回，减少外部 Redis/BM25 服务依赖，检索架构更集中。
- 建立可解释的 RAG 质量体系，不只看答案文本，还检查 Recall@K、MRR、hit_type、source、Prompt Profile、场景隔离和性能。
- 通过 LangSmith 把线上问题沉淀为 Dataset 和 Experiment，形成 Bad Case 持续回归机制。
- 为后续 Agent 化扩展预留边界：RAG 主链路稳定后，可在编排层接入 LangGraph、工具调用和多步骤任务。
