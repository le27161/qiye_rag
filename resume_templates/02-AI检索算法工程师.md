# 简历模板二：AI 检索 / RAG 算法工程师

## 项目名称

**KnowForge 企业知识平台：Milvus 混合检索与 RAG 检索策略优化**

## 项目周期

20XX.XX - 20XX.XX（按实际经历填写）

## 项目背景

企业知识问答既需要语义理解，也需要关键词精确命中。纯向量检索容易漏掉制度编号、字段名称、金额、流程节点等精确词；纯关键词检索又难以处理同义表达和追问。因此项目采用 Milvus Dense + BM25 Hybrid Search，并在召回后引入 CrossEncoder 重排序，通过动态检索计划为 FAQ、知识查询、追问、费用、合规、排障和表格类问题分配不同检索参数。

## 技术栈

| 类别 | 技术选型 |
|---|---|
| 向量模型 | BGE-M3，sentence-transformers 本地推理 |
| 重排序模型 | BGE-Reranker-Large，CrossEncoder |
| 向量数据库 | Milvus 2.5、pymilvus、langchain-milvus |
| 混合检索 | Dense Vector + Milvus `BM25BuiltInFunction` |
| 融合排序 | Milvus weighted ranker，权重配置 `0.55 / 0.45` |
| 检索编排 | `RetrievalPlan` 动态检索计划 |
| 查询增强 | 追问改写、查询变体、多路召回合并去重 |
| 评测指标 | Recall@K、MRR、关键词覆盖率、命中路径准确率、Prompt Profile 准确率 |
| 可观测性 | LangSmith Trace、检索诊断、阶段耗时 |

## 核心功能

1. **Milvus Hybrid Search**：同一 collection 中保留 dense/sparse 两类向量字段，利用 Milvus BM25 Function 为中文文本生成稀疏检索能力。
2. **Weighted Ranker 融合**：通过 langchain-milvus 调用 Milvus 混合检索，以 `weights=[0.55, 0.45]` 融合稠密语义召回和 BM25 精确匹配。
3. **CrossEncoder 重排序**：将初检候选统一交给 BGE-Reranker-Large 精排，提升相关证据排序位置，最终限制进入 Prompt 的上下文数量。
4. **查询变体检索**：对知识查询和追问生成查询变体，多路召回后按 `chunk_id/faq_id` 去重，再统一重排，控制召回效果和重排成本。
5. **动态检索计划**：按意图、短问题、风险类别和表格偏好逐层调整 `faq_top_k`、`doc_top_k`、直出阈值、上下文数量和是否启用变体。
6. **FAQ 高置信直出**：FAQ 命中达到阈值且满足直出条件时返回标准答案；低置信或复杂问题进入文档 RAG。
7. **表格查询优化**：识别费用、金额、清单、行号等表格类问题，扩大文档候选并提高上下文数量，避免相似 FAQ 误直出。
8. **检索诊断**：输出 query variants、top score、source、kb_version、DataScope、prompt_profile 和阶段耗时，辅助定位漏召、误召和排序问题。

## 个人职责

- 负责 Milvus collection schema 和混合检索链路设计，接入 `BM25BuiltInFunction`，统一封装 dense/sparse hybrid search。
- 开发 `MilvusHybridStore.search_many()`，实现多变体检索、候选合并、重复 chunk 去重、候选截断和统一 CrossEncoder 重排。
- 设计 `RetrievalPlan` 动态检索策略，将意图识别结果转换为 FAQ/Doc 检索开关、top_k、阈值、上下文数量和查询变体开关。
- 实现追问场景的查询改写与变体生成，解决“那审批呢”“材料呢”等指代不完整问题的召回不稳定。
- 设计 FAQ 直出策略，将 FAQ 标准答案直出和文档 RAG 生成拆分为两条路径，减少简单问题的 LLM 调用成本。
- 参与构建检索评测体系，基于评测集统计 Recall@K、MRR、关键词覆盖率、source 命中率、Prompt Profile 命中率等指标。
- 通过 LangSmith Trace 记录检索参数、召回结果和耗时，支持 Bad Case 分析与 Experiment 对比。

## 项目成果

- 完成 Dense + BM25 + CrossEncoder 的三阶段检索架构，兼顾语义召回、精确词匹配和排序质量。
- 通过动态检索计划将不同问题类型拆分处理，避免 FAQ、复杂知识查询、追问和表格查询共用一套固定参数。
- 多变体检索支持同义表达和历史追问召回，候选合并后统一重排，降低重复重排带来的性能浪费。
- 建立检索回归评测口径，可按场景、source、hit_type 和 Prompt Profile 分组观察退化。

## 简历使用建议

- 不要写“自研 BM25 引擎”，本项目主链路使用的是 Milvus 2.5 内置 `BM25BuiltInFunction`。
- 不要写“RRF 融合”，当前实现采用 weighted ranker。
