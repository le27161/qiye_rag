## 准确性处理

| 主题 | 参考材料所展示的设计 | 本文的处理 |
| --- | --- | --- |
| 存储 | MySQL 业务库与元数据库，Qdrant 字段/指标，ES 字段值 | 明确各自职责，不把整库交易行索引当必要条件 |
| 指标 | 元数据与字段关系帮助生成 SQL | 补充粒度、退款、状态、单位等契约；不照搬可能有歧义的客单价字段公式 |
| ID | 字段可以有多个向量点 | 区分 point ID 与业务 ID，按业务 ID 去重 |
| 上下文裁剪 | 模型筛选候选信息 | 说明选择已有 ID、程序裁剪、保留必要依赖与关联键 |
| SQL 校验 | 使用 EXPLAIN；首次失败后修正一次并直接执行 | 明确基线缺少修正后再次校验；有界重试与重新安全校验属于增强建议 |
| 执行安全 | 基础 SQL 生成与执行闭环 | AST 允许列表、最小权限、行列控制、超时等均作为建议，不冒充原实现已有功能 |
| LangGraph | 状态图与检索分支 | 不将工作流描述成通用自主多 Agent；强调 reducer、汇合、版本语义和测试 |
| 持久化 | 图状态可以配置持久化 | 不等同于长期记忆、外部副作用恰好一次或数据库快照 |
| API | FastAPI 与 SSE、服务层依赖组装 | 事件契约、断线、取消和审计是独立设计讨论，不声称完成前后端联调 |
